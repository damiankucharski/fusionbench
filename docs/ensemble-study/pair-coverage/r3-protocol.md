# Does covering distinct pairs change held-out performance across 25 scenarios?

This prospective series freezes the menu, selection and reporting rules before the first evaluation on the new data seeds.

Generate all 25 fixed families in their standard-v4 preset order, with four fresh banks per family (seeds 243100–243103), 512 fit and 512 test observations per bank. Run the previous ordinary native pooled search once with search seed zero, its historical native founder menu, 16 generations, the usual size objective, unrounded pooled-Brier final-survivor selection, and the adaptive node cap max(31, number of providers + 1). Freeze this one native winner as the incumbent for both new menus. All methods share each bank's original provider order and arrays.

Each menu has eight actual native two-provider proposals. Interleave four MIN and four MAX in that order. Both arms sample unordered, distinct operand indices from all provider columns. For each operator separately, IID draws uniform pairs with replacement and unique draws a uniform permutation without replacement, starting another shuffled cycle whenever the pair palette runs out. The latter still pays for all eight slots when a palette contains fewer than four pairs. For each data seed and each operator index (0 for MIN and 1 for MAX), call NumPy SeedSequence([data_seed, operator_index, 6103]).generate_state(1) and share that unsigned seed between policies. The same schedule applies across families of the same size at the same data seed. The two arms need not draw the same first pair. Binary probes operate on positive-class scores. Multiclass probes operate per class using the native multiclass normalizer, including its uniform fallback on all-zero outputs.

Choose the smallest full-class Brier on fit observations across the ordinary finalist and each menu's eight proposals. Exact ties retain the incumbent, followed by proposal order. The probes do not reproduce. Score the frozen choices on the untouched test block. Retain the ordinary finalist, mean, fit-Brier-ranked Top-N, standardized probability logistic stacking (C=1) and regularized native-pattern OKAPI as references. Each reference is fitted at most once per bank. Record fit and test Brier, selected program and prediction hashes, distinct providers used, archive and menu costs and the proposal pairs actually offered. The full proposal table records held-out Brier after the deployment choices are frozen.

The primary contrast is unique minus IID held-out Brier. Negative values favor pair coverage. Average matched differences across the four data seeds within each family and weight the 25 fixed families equally. Use 10,000 paired bootstrap samples, resampling the four bank indices separately for each family in preset order with NumPy default_rng(97831). Report a two-sided 95% percentile interval, family-level directions (tolerance 1e-12), strongest regressions and gains, how often the incumbent is replaced, unique minus the unchanged ordinary finalist and differences from all four references. The interval describes the data and coupled proposal-seed draws for these fixed scenarios under a single GP search seed. Generalization to new tasks or search seeds requires separate evidence.

Run the panel on one CPU worker, with one numerical thread. Run the normal program against a disposable artificial fixture to check selection or aggregation without using any official data seeds, then execute the frozen panel once.
