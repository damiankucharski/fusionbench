# Can one parameter update repair a native GP tree?

Freeze before new draws on 2026-11-21. The preceding switch study found that the native six-operator GP often selected the right providers while leaving a large fit gap against an achievable one-gate program. This follow-up tests a local improvement on the actual archived fit champion, alongside a continued-GP control. The OKAPI Lab owns the native forced-operand and reassignment operations. FusionBench owns the threshold-event solver, test data and paired evaluation. [Initial switch study](native-switch/README.md) · [Event solver](https://github.com/damiankucharski/fusionbench/blob/208f341/fusionbench/eval/gate_events.py)

Retain the preceding experiment's two label laws, score alphabet, anonymous six providers, 512 fit and 256 disjoint validation rows. Use twelve fresh data seeds 3800 through 3811 and two search seeds 271 and 277. Use 8192 independent test rows with a full, half and abolished FAR switch. Apply the same NumPy native six-operator engine to both training regimes with population six, multiplier two, tournament two and no survivor fitness reuse. Freeze the best unrounded fit candidate at 1200 evaluations before any parameter update. All policies start from exactly that same tree. Validation labels may choose between the original and the revised tree as a secondary deployment rule; they never choose an edit, node, operand or threshold. Score every resulting model on all test label laws.

Compare the untouched training champion against three fixed procedures. Operand-only evaluates every replacement of one ValueNode occurrence (including the root) by each of the other five provider IDs, leaving its topology and operator parameters fixed. Keep the best strict improvement, retaining the incumbent on ties. Threshold-only refits the first threshold in the engine's stored operator order, keeping all other parameters and assignments. If none exists leave the tree as is and count zero additional cost. Combined first performs the operand procedure and then the same threshold procedure on its result. A tree without a threshold stays in the full population of runs. Never use the hidden roles or the true switch threshold to select a coordinate.

For a threshold with M operands, the native wrapper records the true input values (parent's current result first), forces each alternative to obtain per-row whole-tree squared losses, calls the fixed event solver and verifies the chosen value with an ordinary native prediction. The solver checks edge values, candidate breakpoints including exact ties, representatives of intervals, and incumbent. For broad non-dyadic computed operands it directly scores its registered floats using native squared-distance arithmetic. The result for arbitrary binary64 operands is an optimum over those registered floats; the one-gate dyadic reference has the stated complete threshold coverage. Record full training forward counts, threshold candidates considered, row events, fit cost, identity of the edited parameter, elapsed time and cases with no eligible node.

For each local procedure continue the same GP trajectory and compare at two matched expense counts. First give GP as many extra fitness calls as full native training forwards used by the update (including its compulsory checks). Second give it that number plus one full candidate credit for every distinct threshold value examined by the event solver. This second accounting deliberately charges every objective candidate even when its score was obtained by an incremental event sweep. Record the actual node, row-event and run-time costs as separate quantities. Baseline average, ranked-prefix Top-N testing all six prefixes, regularized logistic stacking and the one-gate empirical optimum all use identical fit data and are frozen before testing.

The primary endpoint is combined refinement minus continued GP in conditional excess Brier on the stationary switch law under the conservative candidate-credit match, using fit-selected models. The prespecified secondary endpoints include all three updates versus the original tree and both continued controls, condition on initial threshold presence as a diagnostic, compare held-out validation-gated acceptance, measure linear control and switch disappearance, and check operand-only versus threshold-only. Take within-data-seed restart means before two-sided t intervals. A gain in a subset or at fit alone does not establish an unconditional test benefit. Publish adverse or null results with the frozen-cost comparisons.
