# Three bounded rounds of native-tree improvement

## Shared evaluation

Only original provider predictions enter the deployed native OKAPI tree. Logistic regression on probabilities and on logits are external comparators. Each method sees 640 development examples from the same bank. Report full-class Brier on 2,048 fresh rows per condition. Include unweighted mean and the best development-ranked Top-N prefix. Lower Brier is better. The previous OKAPI reference is the validation-selected native flat, augmented or GP tree from the [native-pattern experiment](../native-pattern/README.md). It uses 448 discovery and 192 validation examples. Its head-fitting method takes scalar objective values. The training objective in these experiments is Brier skill.

Use the 19 scenario seed slots from the public standard v1 preset. Round roots are 2,010,000, 2,110,000 and 2,210,000 respectively. A bank seed is the round root + 1,000 × slot + replicate. Use six independent replicates per scenario in each exploratory round and ten in the final confirmation. Set the primary search seed to the bank seed. Use clean source annotations. Keep all control fits and all selection decisions fixed across test conditions.

The primary loss averages clean, half-dose single-provider replacement and half-dose Gaussian logit noise with weights 0.50, 0.25 and 0.25. Each scenario carries equal weight. Use two-sided paired 95% t intervals across the replicate macro-averages (fixed scenarios). An exploratory promotion requires the upper bound of new minus incumbent joint loss below zero and the clean upper bound below +0.005 Brier. Also report the nine full original generator shifts, separate conditions, costs and per-scenario outcomes. The probes and priors are shared across families. Test-side best candidates are diagnostic only.

## Round 1 · complete shallow candidate features

Hypothesis: a 600-evaluation GP archive sometimes misses useful pairwise interactions even when a logit head could exploit them. Append all two-provider native MIN trees for a discovery shortlist of at most 12 providers. Use all when there are at most 12. Otherwise rank individual providers by discovery fitness and take the strongest 12. Break ties by provider order. Screen after existing GP programs so outputs equal to an earlier feature on discovery rows keep the earlier representative. Allow up to three additional inputs to the head, as before. Keep the GP search, old flat candidate, validation rule and head optimizer unchanged. The candidate receives additional screening work; record its use and cost. Compare choice regret before refitting, test loss before/after fitting head weights on all rows and the actual deployed predictor on all conditions.

## Decision and confirmation

Publish the first result before freezing round 2. If round 1 passes, build on its candidate. Otherwise retain the previous native procedure as the round 2 incumbent. Round 2 will target a different source of loss identified from the diagnostics. Freeze its algorithm, constants and primary endpoint before generating its evaluation banks. Round 3 independently compares the most recently promoted candidate with the original OKAPI. If neither exploratory candidate passes, confirm the exploratory candidate with the smaller joint point difference against original OKAPI. This fallback is exploratory selection, and only round 3 supports a confirmation claim.

In round 3 additionally test a held-out coherent failure: choose the two providers with the highest centered prediction correlation on development inputs and replace both by the same wrong donor row on about half the clean test examples. Use no labels to choose the pair. This condition is secondary and is held out of model development. Repeat both native fits with search seed offset +10,000,000 on the first two data banks per scenario to measure sensitivity with data held fixed. Use eight stratified splits of the real scikit-learn digits example as a separate descriptive test; the splits reuse images. Neither the extra disturbance nor digits enters the promotion rule. No automation is resumed.
