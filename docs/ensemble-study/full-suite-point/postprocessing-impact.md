# Which historical OKAPI scores can change when tasks alternate?

A previously fitted FusionBench model could change its predictions after a different model was fitted in the same Python process. The old adapter set an OKAPI process-wide function at fit time. Every operator in the saved tree consulted that function again at prediction time. Binary trees used a single positive-probability channel with the identity function. Multiclass trees normalized class mass after each operator. Fitting a multiclass model therefore made an earlier binary operator return 1 on every row. In the other direction, normalizing just the final multiclass output can leave errors introduced inside a multi-operator tree. The behavior was present when the native adapter was introduced and at the full-suite protocol's historical pin. [Adapter at introduction](https://github.com/damiankucharski/FusionBench/blob/5999094/fusionbench/methods/okapi.py#L110-L139) · [Adapter at the audited pin](https://github.com/damiankucharski/FusionBench/blob/d00e1a8/fusionbench/methods/okapi.py#L158-L209) · [Native operator evaluation](https://github.com/damiankucharski/OKAPI/blob/76f96bc/okapi/node.py#L213-L224)

## Pinned replay

Two fresh Python processes reproduced the same trees, row-change counts, maximum differences and unrounded losses using FusionBench `d00e1a8` and OKAPI `76f96bc` with one BLAS thread. Each test used 96 held-out rows. Binary Brier below averages the squared error in the positive probability, and multiclass Brier sums squared errors over classes before taking the row mean.

| Old fitted model | Another model fitted before re-use | Rows changed / 96 | Brier immediately after fit | Brier on re-use |
|---|---|---:|---:|---:|
| Binary Committee | Either tested multiclass model | 96 | 0.12984554 | 0.52083333 |
| 5-class MulticlassCommittee | Binary Committee | 96 | 0.71746828 | 0.73009857 |
| 4-class Saturated | Binary Committee | 24 | 0.20419577 | 0.20419577 |

The 5-class maximum probability change was 0.35319. The 4-class winner contained one MIN. Its maximum change was 2.22 × 10⁻¹⁶. Fitting the binary task again restored the first binary model's original predictions exactly.

To reproduce, build `Committee()` and each of `Saturated()` and `MulticlassCommittee()` with `build(n_per_split=96, seed=487)`. For each pair, fit a fresh `OKAPIMethod(seed=1207, n_restarts=1, generations=3, fitness="brier")` on each dataset's fit split, passing its task and class count. Fit binary, record its test predictions, fit multiclass, record its test predictions, predict again with the earlier binary model, fit a fresh binary model, then predict again with the earlier multiclass model. Compare each model against its own initial test predictions.

We found no archived score that the traced cross-task overwrite invalidates. The search covered the 15 tracked Python files naming the public adapter or its shrinkage wrapper at `d00e1a8`, callers of the method registry and runner, native postprocessor setters and research/example entry points. There were no tracked notebooks or shell scripts at that pin. The archived tables establish what the project reported. They contain no process-wide call trace and cannot certify other invocations. Interactive reuse, a model service retaining different task types, concurrent mixed-task calls, or direct tree evaluation in an already modified process were exposed under the old code. The two independent process replays above demonstrate an actual failure for retained models. The companion OKAPI audit covers archived binary measurements and the matching reference. [Independent OKAPI historical audit](https://github.com/damiankucharski/OKAPI/blob/fa4ba5a/experiments/standard_point_control/historical_impact.md)

The full-suite driver now scopes native search and tree prediction by task. OKAPI supplies a context-local override and the FusionBench adapter applies it at fit and predict. The same bidirectional replay changed zero rows in both tasks on both the newer OKAPI core and the adapter's legacy-core fallback. Both alternating-task regression tests also passed with the new core.
